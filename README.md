## 🔍 Framework Overview

Logic-V separates frozen multimodal perception from trainable language
reasoning.

A frozen vision-language model first converts each source video into a
structured textual evidence log. Logic-V then aligns a compact
Qwen2.5-3B-Instruct reasoning policy using Group Relative Policy
Optimization (GRPO), with:

1. an entropy-aware blind-review reward for trajectory-to-decision
   consistency; and
2. a lexical trajectory-stability reward defined over qualified correct
   trajectories.

At inference time, the Agentic Verification Framework (AVF) reuses the
same aligned 3B policy under three complementary role instructions:

- **Generalist:** broad semantic interpretation;
- **Navigator:** temporal and trajectory reasoning;
- **Observer:** strict evidence grounding.

The Consensus and Hostile Verification (CAHV) cascade resolves supported
local predictions and selectively invokes a frozen
Qwen2.5-32B-Instruct-AWQ verifier only for structured disagreement cases.

> [!IMPORTANT]
> **Reasoning-stage modality**
>
> The trainable Logic-V policy does not process raw video directly. It
> reasons over structured textual evidence logs generated by a frozen
> perception model. Comparisons involving direct-video systems are
> therefore reported as reference comparisons rather than controlled
> reasoning-stage comparisons.

This repository provides:

- training and inference code;
- released LoRA weights;
- derived textual evidence logs;
- raw prediction outputs;
- AVF/CAHV evaluation scripts;
- routing records and additional analysis artifacts.

## 🏆 Key Results

### Main reported results

| Benchmark | Configuration | Accuracy | Evaluation setting |
| :--- | :--- | ---: | :--- |
| VSI-Bench + UrbanVideo-Bench | AVF | **36.84%** | 22.5% verifier rate; measured 38.5 GB stage-wise peak |
| EgoSchema | Logic-V single-pass | **59.0%** | 3B reasoning policy |
| EgoSchema | AVF | **59.4%** | 14% verifier rate; 86% avoid external verification |
| MVBench | AVF | **45.0%** | +5.9 points over the corresponding 3B-SFT baseline |
| Video-MME long-form subset | AVF | **37.1%** | +11.9 points over the corresponding 3B-SFT baseline |
| MedQA-USMLE pilot | AVF | **63.7%** | Structural transfer probe; 56.6% single-pass baseline |

### Interpretation notes

- The VSI/Urban result is obtained from textual evidence logs generated
  by the frozen Qwen2.5-VL-7B-Instruct perception model.
- The EgoSchema controlled reasoning comparison uses identical
  Qwen2.5-VL-72B-Instruct-AWQ evidence logs across the compared
  reasoning systems.
- The overall EgoSchema difference from 59.0% to 59.4% should be
  interpreted as practical comparability rather than a large aggregate
  improvement.
- The benefit of AVF on EgoSchema is concentrated on routed
  disagreement cases.
- On the 14% verifier-escalated EgoSchema subset, majority voting reaches
  35.7%, whereas selective external verification reaches 61.4%.
- The MVBench and Video-MME improvements are measured against the
  corresponding 3B-SFT systems consuming the same derived evidence logs.
- The MedQA experiment is a structural cross-domain transfer probe and
  is not presented as a clinical-performance claim.

<details>
<summary><b>🔎 Transparency: raw predictions and reasoning traces</b></summary>

<br>

The `evaluation/` directory contains raw model prediction files used for
result inspection and error analysis.

These outputs are not manually rewritten or selectively curated. They
include successful deductions as well as imperfect generations, such as:

- formatting drift;
- unsupported assumptions;
- incomplete reasoning;
- role-level disagreement;
- invalid or partially malformed outputs.

The generated reasoning content is preserved as produced by the model.
Some files may contain parser-added metadata used by the automated
evaluation pipeline.

For example, a trailing marker such as:

```text
[Generation Cleaned]
```

indicates that the evaluation parser successfully extracted a final
multiple-choice decision. It does not mean that the reasoning trace was
manually rewritten.

The released predictions support inspection of:

- successful grounded reasoning;
- failure cases;
- output-format behavior;
- role-level disagreement;
- CAHV routing outcomes;
- external-verifier decisions.

</details>

## 🚀 Installation

### 1. Clone the repository

```bash
git clone https://github.com/bitxige/Logic-V-Reasoner.git
cd Logic-V-Reasoner
```

### 2. Create an isolated Python environment

Python 3.10 or later is recommended.

```bash
conda create -n logic-v python=3.10 -y
conda activate logic-v
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

The implementation uses packages including:

- `ms-swift`;
- `transformers`;
- `accelerate`;
- `deepspeed`;
- `peft`;
- `qwen-vl-utils`.

CUDA, PyTorch, and quantization-library versions should be selected
according to the target GPU environment.

## 📥 Released LoRA Weights

The repository releases a 5600-step Logic-V LoRA checkpoint used by the
provided inference scripts.

Create the target directory:

```bash
mkdir -p checkpoint/checkpoint-5600
```

Download the adapter weights:

```bash
wget \
  https://github.com/bitxige/Logic-V-Reasoner/releases/download/v1.0/adapter_model.safetensors \
  -O checkpoint/checkpoint-5600/adapter_model.safetensors
```

Ensure that the corresponding adapter configuration file is also
present:

> `Qwen/Qwen2.5-3B-Instruct` base model. Adjust local paths according to
> the actual repository layout.

## 📊 Reproducing the Evaluations

All evaluation scripts are located in the `inference/` directory.

> [!TIP]
> Replace placeholder paths with the actual locations of the downloaded
> benchmark files, derived evidence logs, model checkpoints, and local
> inference services.

### A. Logic-V single-pass evaluation

This configuration evaluates one reasoning pass from the aligned 3B
policy without role-conditioned AVF routing.

```bash
python inference/eval_rl_single_pass.py \
    --base_model_path "Qwen/Qwen2.5-3B-Instruct" \
    --model_path "checkpoint/checkpoint-5600" \
    --input_file "evaluation/egoschema_72B-Int4_analysis.jsonl" \
    --output_file "evaluation/RL-egoschema_predictions.jsonl"
```

The reported EgoSchema single-pass accuracy is approximately:

```text
59.0%
```

### B. SFT baseline evaluation

```bash
python inference/eval_sft_egoschema.py \
    --base_model_path "Qwen/Qwen2.5-3B-Instruct" \
    --lora_path "checkpoint/Qwen2.5-3B-Video-SFT/checkpoint-504" \
    --input_file "evaluation/egoschema_72B-Int4_analysis.jsonl" \
    --output_file "evaluation/sft_egoschema_predictions.jsonl" \
    --max_new_tokens 1024
```

### C. Full AVF/CAHV evaluation

This configuration:

1. samples five trajectories for each of the Generalist, Navigator, and
   Observer roles;
2. forms role-level and pooled vote statistics;
3. applies the calibrated CAHV rule cascade;
4. selectively sends structured disagreements to the external
   Qwen2.5-32B-Instruct-AWQ verifier.

```bash
python inference/eval_avf.py \
    --base_model_path "Qwen/Qwen2.5-3B-Instruct" \
    --model_path "checkpoint/checkpoint-5600" \
    --input_file "evaluation/egoschema_72B-Int4_analysis.jsonl" \
    --output_file "evaluation/avf_egoschema_predictions.jsonl" \
    --n_votes 5 \
    --arbiter_api_url "http://localhost:8000/v1/chat/completions" \
    --arbiter_model_name "Qwen/Qwen2.5-32B-Instruct-AWQ"
```

> [!NOTE]
> The command-line arguments retain the legacy names
> `--arbiter_api_url` and `--arbiter_model_name` for compatibility with
> the released implementation. In the manuscript, this component is
> described as the **external verifier**.

The reported EgoSchema AVF accuracy is approximately:

```text
59.4%
```

The external verifier is activated for approximately 14% of EgoSchema
queries. The remaining 86% are resolved without external verification.

## 🎞️ Frozen-Perception Evidence Extraction

The evidence-extraction scripts convert raw benchmark videos into
structured textual evidence logs.

For the EgoSchema fixed-perception analysis, the reported configuration
uses Qwen2.5-VL-72B-Instruct-AWQ with a 24-frame budget.

```bash
python scripts/analyze_egoschema_pipeline.py \
    --model_path "Qwen/Qwen2.5-VL-72B-Instruct-AWQ" \
    --video_dir "path/to/your/downloaded/videos" \
    --input_json "path/to/your/downloaded/egoschema.json" \
    --output_file "evaluation/egoschema_72B-Int4_analysis.jsonl" \
    --max_frames 24
```

> [!NOTE]
> The 72B vision-language model serves as a **frozen perception model**.
> Its outputs are used as structured evidence logs. It does not provide
> teacher-generated rationales, demonstrations, or distillation
> supervision to the Logic-V policy.

The reported Task-Adaptive Perception Protocol assignments are:

| Benchmark | TAPP mode | Query usage |
| :--- | :---: | :--- |
| VSI-Bench | Mode II | Query-blind |
| UrbanVideo-Bench | Mode II | Query-blind |
| MVBench | Mode I | Global-Glimpse extraction |
| EgoSchema | Mode II | Query-aware |
| Video-MME | Mode III | Query-aware sparse anchors |

Further details are provided in:

[Supplementary_Information.pdf](./Supplementary_Information.pdf)

## 🧪 Training Configuration

The reported training run uses:

- Qwen2.5-3B-Instruct as the trainable policy;
- Qwen2.5-7B-Instruct as the frozen blind-review judge;
- LoRA rank 32 and scale 64;
- GRPO group size \(K=4\);
- learning rate \(5\times10^{-6}\);
- KL coefficient \(\beta=0.005\);
- sampling temperature 0.7;
- 12 training epochs;
- training seed 3407.

The reported run was conducted on two 48 GB NVIDIA Ampere vGPU
instances:

- one device hosted policy optimization;
- the other hosted frozen-judge inference.

The two devices executed distinct components of the training pipeline.
This separation decoupled policy optimization from judge inference and
improved training throughput. It did not partition an individual model
through distributed model parallelism.

Complete reward definitions and optimization settings are provided in
the manuscript and the companion document:

[Supplementary Information](./Supplementary_Information.pdf)

## 🛡️ Reproducibility and Hardware Notes

The reported evaluation pipeline executes evidence extraction, compact
reasoning, and selective external verification sequentially on one
48 GB GPU.

Measured stage-wise peak memory:

| Evaluation setting | Measured peak |
| :--- | ---: |
| VSI-Bench + UrbanVideo-Bench | 38.5 GB |
| EgoSchema evidence extraction | 42.5 GB |
| EgoSchema AVF reasoning and verification | 38.5 GB |
| EgoSchema complete stage-wise maximum | 42.5 GB |

These values are stage-wise peak-memory measurements. They do not
establish lower total computation, lower latency, or lower energy
consumption than every reference system.

Exact regeneration may vary slightly because of:

- stochastic decoding;
- CUDA nondeterminism;
- differences in GPU architecture;
- quantization kernels;
- library versions;
- inference-server configuration.

For transparent comparison, the repository provides the raw prediction
outputs used to calculate the reported results.

## ⚠️ Scope and Limitations

The current release should be interpreted under the following scope
conditions:

- reinforcement training uses one reported seed;
- the policy, judge, and verifier belong to the Qwen2.5 model family;
- CAHV uses manually configured rules derived from a disjoint
  30-example calibration set;
- the trajectory-stability reward measures lexical-set overlap rather
  than formal logical equivalence;
- AVF samples 15 compact-policy trajectories per query;
- selective verification reduces large-verifier activation but does not
  guarantee lower total latency or energy consumption;
- EgoSchema uses a frozen 72B-INT4 perception model;
- the MedQA experiment is a structural transfer probe rather than a
  clinical-performance benchmark.
