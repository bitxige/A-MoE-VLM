> [!IMPORTANT]  
> **Language-Only Reasoning:** AVF does **not** process any visual input directly. Instead, it reasons over structured text evidence logs pre-extracted by a large VLM (e.g., Qwen2.5-VL-72B). This decoupled design is our core contribution, allowing massive performance gains on strict hardware constraints.

This repository provides the **full reproduction code, pre-trained weights, and raw evaluation artifacts** for the AVF framework, which achieves state-of-the-art causal video reasoning on **EgoSchema** using only a **3B-parameter language model**.

## 🏆 Key Results

Performance on the EgoSchema causal video reasoning benchmark (500-question subset):

| Reasoning Method | Accuracy | Parameters | Modality |
| :--- | :---: | :---: | :---: |
| **Single RL Expert (Ours)** | **59.0%** | 3B | Text Logs |
| **Full AVF Framework (CAHV)** | **60.8%** | 3B | Text Logs |

<details>
<summary><b>🔍 Transparency Note: Why we open-source raw predictions (Click to expand)</b></summary>
<br>
A core claim of our paper is that our Logic-V reward signal produces authentic but imperfect reasoning. To ensure full scientific transparency, we do <b>not</b> cherry-pick or post-process results. 

Our model's outputs are occasionally messy and contain artifacts of the RL training process. This is **expected and by design**—the AVF routing architecture exists precisely to handle such cases. Inside the `evaluation/` directory, we explicitly provide our **unprocessed RL test result QA pairs (raw `.jsonl` prediction logs)** containing the complete `<think>` traces generated by our agent.

You can directly inspect the successful causal deductions, as well as its flawed artifacts (e.g., formatting drifts like `<think>\n <think>`), which explicitly validates the necessity of the AVF routing architecture.

> **Note on `[Generation Cleaned]` tags:** You may notice this tag at the end of some JSON responses. This is merely a programmatic artifact appended by our automated regex parser after successfully extracting the final multiple-choice answer. **The `<think>` reasoning traces themselves remain 100% raw and unaltered.**
</details>

## 🚀 1. Quick Start & Installation

Clone this repository and set up the environment. We highly recommend using **Python 3.10+** and **CUDA 11.8+**.

```bash
git clone https://github.com/[ANONYMIZED]/AVF.git
cd AVF
```

Install the core dependencies (including `ms-swift`, `DeepSpeed`, and `qwen-vl-utils`):

```bash
pip install -r requirements.txt
```

## 📥 2. Download Pre-trained Weights

To facilitate immediate reproduction, we fully open-source our 5600-step RL LoRA weights. You do not need to retrain the model from scratch.

Download the `adapter_model.safetensors` and place it in the `checkpoint/checkpoint-5600/` directory:

```bash
mkdir -p checkpoint/checkpoint-5600

# Download the core weights (228MB)
wget https://github.com/[ANONYMIZED]/AVF/releases/download/v1.0/adapter_model.safetensors \
  -O checkpoint/checkpoint-5600/adapter_model.safetensors
```

> [!WARNING]  
> Ensure that the accompanying `adapter_config.json` is also placed in the same directory. Adjust paths if your local folder naming differs.

## 📊 3. Reproducing Evaluations (Inference)

All evaluation scripts are neatly organized in the `inference/` directory.

> [!TIP]
> **Path Notice:** The exact filenames for your scripts or datasets might vary based on your local setup. Please verify and replace the placeholder paths in the commands below with your actual local file paths.

### A. Evaluate Single RL Expert (~59.0%)
Runs the single generalist expert trained via the Logic-V reward pipeline.

```bash
python inference/eval_rl_single_pass.py \
    --base_model_path "Qwen/Qwen2.5-3B-Instruct" \
    --model_path "checkpoint/checkpoint-5600" \
    --input_file "evaluation/egoschema_72B-Int4_analysis.jsonl" \
    --output_file "evaluation/RL-egoschema_predictions.jsonl"
```

### B. Evaluate SFT Baseline
For performance comparison against the standard supervised fine-tuned (SFT) model:

```bash
python inference/eval_sft_egoschema.py \
    --base_model_path "Qwen/Qwen2.5-3B-Instruct" \
    --lora_path "checkpoint/Qwen2.5-3B-Video-SFT/checkpoint-504" \
    --input_file "evaluation/egoschema_72B-Int4_analysis.jsonl" \
    --output_file "evaluation/sft_egoschema_predictions.jsonl" \
    --max_new_tokens 1024
```

### C. Evaluate Full AVF Framework (~60.8% SOTA)
To reproduce our peak performance, this script activates the **Consensus & Hostile Verification (CAHV)** routing protocol. It dynamically instantiates the *Generalist, Navigator, and Observer* experts using the shared 3B core, escalating high-entropy deadlocks to the 32B-INT4 Arbiter via API.

```bash
python inference/eval_avf.py \
    --base_model_path "Qwen/Qwen2.5-3B-Instruct" \
    --model_path "checkpoint/checkpoint-5600" \
    --input_file "evaluation/egoschema_72B-Int4_analysis.jsonl" \
    --output_file "evaluation/avf_egoschema_predictions.jsonl" \
    --n_votes 5 \
    --arbiter_api_url "http://localhost:8000/v1/chat/completions" \
    --arbiter_model_name "Qwen/Qwen2.5-32B-Instruct-AWQ"
```

## 🧠 4. Teacher Annotations & Logic-V Reward

We provide the exact scripts used to generate the logical reasoning anchors and dynamic visual features from the 72B teacher model.

### Extract Visual Logs & ORB Keyframes (72B-Int4)
This script utilizes an ORB-based homography extraction pipeline to filter redundant frames and uses Qwen2.5-72B to build chronological semantic logs.

```bash
python scripts/analyze_egoschema_pipeline.py \
    --model_path "Qwen/Qwen2.5-VL-72B-Instruct-AWQ" \
    --video_dir "dataset/videos" \
    --input_json "dataset/egoschema.json" \
    --output_file "evaluation/egoschema_72B-Int4_analysis.jsonl" \
    --max_frames 24
```

### Logic-V Reward Engineering
The core logic for our RL pipeline (checking logical consistency via external arbiters and formatting) is located in the `scripts/train/` directory (e.g., `rewards.py`).

## 🛡️ Reproducibility Note

> [!NOTE]  
> The reported accuracy (59.0% for the RL single-expert) was evaluated using `bfloat16` precision on a **single 48GB GPU** (e.g., vGPU-48GB / RTX 4090 / A800), which is highly efficient and more than sufficient for inference. *(During RL training, a dual-GPU setup was utilized solely for acceleration.)*
> 
> Due to the inherent non-determinism in parallel CUDA operations, architectural variations in `bfloat16` matrix multiplications across different GPU models, and specific environment configurations, **you may observe natural minor fluctuations in the final reproduced accuracy.** To ensure absolute transparency, our **exact raw prediction logs** containing the complete `<think>` traces are provided in the `evaluation/` directory as the definitive ground-truth.
